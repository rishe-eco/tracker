## Built

- **`api/src/graphql/auth.ts`:** `requireReflectSession` and `REFLECT_SESSION_ONLY` ("Reflect is only available in the app, not to API tokens."). Every Reflect operation is `requireAuth(requireReflectSession(...))`, so no user is still `Unauthorized` and a token, read or write, gets the session-only message (D-12, convention 11).
- **`api/src/services/reflect/`** (new): `refusals.ts` (§6.2's messages as one table), `state.ts` (`ensureReflectState` under `withUserLock("rfl-state:…")`, create-then-recover; `pinnedVersions`, a read that never writes), `palettes.ts` (PD-8: the first 2 `early` and 4 `broaden` feelings and the first 5 needs of the pinned F&N pack), `entry.ts` (start, save, saveMoment, saveReading, move, stop, finish, answer, remove, listPast, getPast, getHome, getOpenEntry) and `content.ts` (`reflectContent` and the home's served-pack fields, always `DIALS.practiceLocale`).
- **SDL:** a `# ── Reflect ──` block of 6 enums and 21 types before the F&N banner (D-2); 5 queries and 9 mutations under `# ── Reflect` comments. `typeResolvers.ts` maps the six enums to their stored lowercase values, serialises dates as ISO strings and orders moments and readings by `position`.
- **`api/src/test/helpers.ts`:** `clearDb` deletes the four Reflect tables ahead of `user`.
- **Tests:** `reflect.integration.test.ts` (new, 28) and three describes added to `reflectFences.unit.test.ts` (the SDL half, the token refusal over every Reflect resolver, the model-call half; 22 in the file). The review extended two scanners (below).

No client file, `common.json` key, schema change, migration or dependency.

## Decided

The card's *Decided here*:

1. **`requireReflectSession` in `graphql/auth.ts`.** *Accepted.* `mutations.ts`'s private `requireSession` for token management is untouched, so two session guards exist with different messages, as intended.
2. **`ReflectState` is written on the first `startReflectEntry` only; reads serve `CURRENT_VERSION` without writing.** *Accepted.* Tested ("reads write nothing"), and on the running server a write-token `startReflectEntry` was refused before `ensureReflectState` ran.
3. **Word source, met and the two pre-check answers are GraphQL enums, stored lowercase.** *Accepted.* Round-tripped over HTTP: `PALETTE`, `OWN`, `UNMET`, `WEEKS`, `NO` in, the same out; `NOWHERE` refused by the schema.
4. **A move to the current step returns the entry unchanged.** *Accepted.*
5. **Bounds count `.length` (UTF-16 units).** *Accepted.* 70 emoji fit a 140 scene, 71 don't.
6. **Services write `createdAt` and `closedAt` from `new Date()`; tests fake `Date` only.** *Accepted.* The suite's clock is 2031-03-01, so nothing depends on today.
7. **The `before` cursor orders by `createdAt` desc, then `id` desc; an unowned `before` is `Not found`.** *Accepted.* Probed over HTTP with another user's id.
8. **No text is trimmed; only `""` becomes null.** *Accepted.*
9. **No new dependency.** *Accepted:* none added.

The lane's own calls (report part 4):

- **Enum mapping in `typeResolvers`.** *Accepted:* services and columns see only the stored form.
- **`ensureOwned` inside the services, with `ctx.user.id` from the resolver.** *Accepted:* it matches Noticing, and every path is one `findUnique` then `Not found` (D-9's timing).
- **Every Reflect write for one user under `withUserLock("rfl-entry:…")`, not only start.** *Accepted:* it makes the position-count check atomic with its write; the unique key stays as the backstop. The lock is in-process, as everywhere in Tracker.
- **A `replacing` that isn't the open entry's id returns the open entry and closes nothing.** *Accepted.* Probed with a closed id, an unknown id, and a double tap after a replace: each returned the open entry.
- **Moment and reading positions:** non-integer, negative, `>= 3` or past the next free one give the at-most-three refusal. *Accepted.* GraphQL refuses `1.5` before the service; `2147483647` gets the refusal.
- **The 60 bound on a feeling or need whatever the source.** *Accepted.*
- **Pre-check arguments: `null` and omitted are the same; a non-null value off `precheck` is the step refusal.** *Accepted.*
- **`answer`: a stranger's id is `Not found` first, then the answer refusal.** *Accepted.*
- **`storyStart` drops a trailing half surrogate pair.** *Accepted,* by reading: it trims only when the story ran past 80 units and the cut fell inside a pair.
- **`reviewStatus` on the home and the content is Reflect's pack's.** *Accepted.*
- **`metOptions.not_sure` is `notSure` in GraphQL.** *Accepted.*
- **`prompts` fully typed; `limits` also carries `storySoftLine`, `ownWord` and the caps.** *Accepted:* all are §6.4 values the client needs, and none is lexicon. The whole content query resolved over HTTP with no null in a non-null field.
- **The SDL fence also refuses `lexicon` and `lastCatchAt`.** *Accepted:* §6.5 lists both.
- **The through-the-schema test uses `ApolloServer.executeOperation`.** *Accepted;* the dual-module cause wasn't rechecked, since the test passes and runs the app's own server class.

## Owed

- **`reflectPastEntry` returns `step`, which tells a stopped entry from a finished one** whenever it was stopped before `close` (a finished entry is always at `close`). Plan D-9 lists "whether an entry was stopped" among the things never shown back and gives B2 "`outcome` kept out of the API", while §6.1 has the past entry return the whole `ReflectEntry`. AC-3's text names only the pre-check answers, the after-entry answer and the catches, so this isn't B2's acceptance failing, and the shape is the plan's. The founder decides, before B6's card: a past-entry type without `step` (B6 doesn't draw a step), or the leak accepted in D-9. *Owed to later stages*, needed by B6.
- **The deploy check** (the card's *What the verify deploys*): after the push, an unauthenticated `POST /graphql` with `{ reflectHome { hasPast } }` returns `Unauthorized`; a schema without the field would say `Cannot query field`. It is the pushing session's, with a bot user agent so it isn't counted as a visit. Locally the same request on the running server returned `Unauthorized`.
- **The founder's sign-in on the live site after this deploy:** the 14 operations are live and unlinked; nothing else changes. It joins B1's row in *Past the verification ceiling*.
