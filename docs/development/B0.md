## Built

- **`client/e2e/ports.ts`** (new): the one source of the e2e ports, the API, health and web URLs, and the per-slot credentials file. `E2E_API_PORT` defaults to `4010`, `E2E_WEB_PORT` to `5183`. At the review it gained a refusal: a port that isn't a whole number from 1 to 65535, a dev server's `4000` or `5173`, or one port for both throws before anything starts.
- **`client/playwright.config.ts`:** `channel: process.env.PW_CHANNEL ?? "msedge"`. Two `webServer` entries with their own `env` and `cwd`: the API clears and rebuilds a scratch SQLite file and runs `npx ts-node src/index.ts`; the web is `npx vite --port <web> --strictPort` with `VITE_API_URL`. `reuseExistingServer` only with `E2E_REUSE=1`. A guard throws unless the database URL ends in `e2e.db` and names no `dev.db`, `test.db` or `prod.db`. `outputDir` and the html report folder are per API port.
- **`client/e2e/clearScratchDb.mjs`** (new, at the review): deletes the scratch database with its `-wal`, `-shm` and `-journal` files before `prisma db push --force-reset`. It refuses any name that isn't a scratch `e2e.db`.
- **`client/e2e/globalSetup.ts`, `helpers/api.ts`, `helpers/auth.ts`:** read the API URL and the credentials file from `ports.ts`. No `localhost:4000` or `5173` URL is left in `client/e2e`; the only two literals are `ports.ts`'s refusal list.
- **`client/vite.config.ts`:** `cacheDir: process.env.E2E_VITE_CACHE_DIR ?? "node_modules/.vite"`. The default is Vite's own, so `npm run dev` and the build are unchanged.
- **`client/.gitignore`:** `/e2e/.auth/` in place of `/e2e/.auth/e2e-user.json`.
- **`client/e2e/README.md`** (new): the variables, the refusals, the slots, `E2E_REUSE=1`, and the Windows excluded-ports note.

No app code, schema, API, strings or dependencies changed.

## Decided

The card's *Decided here*:

1. **`npx ts-node src/index.ts`, not `tsx`.** *Accepted:* it starts in a worktree (seen at the review, about 8 s).
2. **One shared `client/e2e/ports.ts`.** *Accepted,* and it is where the review's port refusal went.
3. **No `.gitignore` line for the scratch database.** *Accepted:* `api/.gitignore` ignores `*.db`, `*.db-wal`, `*.db-shm` and `*.db-journal` at any depth; `git status --ignored` shows `api/prisma/prisma/` ignored.
4. **The plan's default ports stand** although Windows excludes 3931–4030 today. *Accepted:* the README says to check `netsh` and set the variables.

The lane's own calls:

- **A scratch database per API port** (`api/prisma/prisma/p<port>-e2e.db`), not one `e2e.db`. *Accepted:* two slots in one worktree would otherwise reset each other's database mid-run.
- **A credentials file per API port** (`e2e/.auth/e2e-user.<port>.json`), so `.gitignore` ignores the folder. *Accepted:* a token is valid only in the database of the API that issued it.
- **`outputDir` and the html report per API port.** *Accepted.*
- **The API wait URL is `/.well-known/apollo/server-health`.** *Accepted, cause checked:* the API is `apollo-server-express` 3, which serves that route, and only after `server.start()`, so a 200 means GraphQL is ready. A bare GET of `/graphql` without `Accept: text/html` gets 400, as the lane said.
- **A Vite cache per web port** through a new `E2E_VITE_CACHE_DIR`. *Accepted:* it touches `vite.config.ts`, which the card didn't name, but the default is Vite's own and the build is unchanged.
- **`helpers/auth.ts` changed too.** *Accepted:* it hard-coded the credentials file.

The review's calls:

- **Refuse a malformed or dev-server port** (`f46b029`). `E2E_API_PORT=""` became port 0 and `abc` became `NaN`: the API started where nobody polled, and the run timed out. `4000` or `5173` with `E2E_REUSE=1` reused the dev server and signed users up in the dev database, which is the failure B0 exists to prevent.
- **Delete the scratch database's side files before the push** (`b81eb6a`). A second run on the same slot failed in `globalSetup` with "The table `main.User` does not exist in the current database." The API runs SQLite in WAL mode, and Playwright kills it rather than closing it, so `-wal` and `-shm` outlive the run. `prisma db push --force-reset` then truncated the `.db` to 0 bytes, read the old schema through the stale WAL, reported "in sync" in 15 ms and wrote nothing. The lane's runs passed because its earlier attempts had left no populated WAL.
- **The API's start timeout is 300 s, not 120 s** (`b81eb6a`). With fresh files, `db push` took 7–8 s at first and then 58–63 s, five times in a row, on an idle disk (CPU 13–19 %, disk 0–2 %). Two slots at once then ran past 120 s. The cause of the slowdown isn't known; the push writes about 40 tables, each with a sync.
